01

Problem

“Return JSON” is not a reliability guarantee.

A language model can produce syntactically valid JSON and still violate the schema expected by an API, database or downstream program. Constrained decoding tries to solve that problem during generation rather than repairing the output afterwards.

The project asks a practical question: once JSON Schema is turned into generation constraints, how much reliability do we actually gain, and where do failures move — compilation, generation, or final validation?

02

Approach

A pipeline built to expose the failure stage.

Instead of keeping only a global score, each schema is followed through the full constrained-generation workflow.

Key finding

The global gap is mainly a compilation-coverage gap.

Once a schema has compiled, Outlines and Guidance are almost tied in success rate. Guidance’s higher overall score is largely explained by accepting substantially more schemas in this experimental setup.

04

Failure analysis

Same objective, very different failure profiles.

The framework choice changes where the bottleneck appears.

OutlinesFSM-based

Failures happen early.

Most failures concentrate at compilation. Logical operators such as not, oneOf, anyOf and if make FSM construction difficult or expensive.

3,770compilation failures
Guidanceinterleaved generation

Failures happen later.

Guidance rejects unsupported constraints more cautiously, but its main remaining issue is generation timeout on long or complex schemas.

836generation timeouts
Experimental caveat

The pipeline used a 60-second compilation timeout, which structurally penalizes Outlines. These numbers describe this experimental setup, not a universal ranking of the frameworks.

05

Setup & limits

Reproduction under real compute constraints.

Experiments ran on Sorbonne University’s shared PPTI infrastructure using Tesla V100-SXM2 GPUs, Outlines v0.1.8, Guidance v0.3 and Llama-3.1-1B-Instruct.
