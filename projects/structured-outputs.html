Structured Outputs for LLMs

JSON Schema & Constrained Decoding

Reproduction and extension of JSONSchemaBench to study how constrained-decoding frameworks improve the reliability of structured JSON generation with LLMs — and where they still fail.

Problem

Making LLM outputs reliable enough for software

Prompting a model to “return JSON” does not guarantee that the result is syntactically valid or that it satisfies a target JSON Schema. Constrained decoding addresses this by restricting the tokens that can be generated at each step so the output remains compatible with a formal specification.

The project studied the practical trade-off behind that promise: a framework must not only enforce the schema, but also compile complex constraints, finish generation in reasonable time, and remain robust across real-world schemas.

Approach

From schema to validated output

The experiments separate failures by stage instead of reducing everything to one global score.

01

JSON Schema

Take a target schema from JSONSchemaBench.

02

Compile constraints

Translate the schema with Outlines or Guidance.

03

Generate

Run constrained generation with Llama-3.1-1B-Instruct.

04

Validate

Check the final instance with an external JSON Schema validator.

Pipeline A — end-to-end generation

Measures the complete system: schema compilation, constrained generation and final validation. Failures are categorized as compilation, generation or validation errors.

Pipeline B — feature-level evaluation

Removes the LLM from the loop and tests compiler behavior directly against controlled valid and invalid instances from the JSON Schema Test Suite.

Main insight

The global gap mostly comes from compilation coverage, not post-compilation generation quality.

Once compilation succeeds, Outlines and Guidance are almost tied in success rate (88.6% vs 89.5%). Guidance’s much higher overall score is mainly explained by its ability to accept more schemas in this setup.

Failure analysis

Different frameworks fail at different stages.

Outlines

Early failures

Failures are dominated by compilation issues. Logical operators such as not, oneOf, anyOf or if can make FSM-based compilation expensive or unsupported.

Guidance

Later failures

Guidance rejects unsupported features more cautiously, then generally preserves conformity. Its main remaining failure mode is generation timeout on long or complex schemas.

Important limitation: the pipeline used a 60-second compilation timeout, which structurally penalizes Outlines. The report therefore treats these numbers as experimental results under a specific setup, not universal framework rankings.

Experimental setup

Reproduction under real compute constraints

Experiments ran on Sorbonne University’s shared PPTI GPU infrastructure, primarily on a server equipped with Tesla V100-SXM2 GPUs. The project used Outlines v0.1.8, Guidance v0.3 and Llama-3.1-1B-Instruct.

Shared VRAM, storage constraints, timeouts, crashes and dependency/version issues shaped the scope of the reproduction. A watchdog mechanism was used to relaunch interrupted experiments, and the analysis prioritized failure causes over an exhaustive latency benchmark.
